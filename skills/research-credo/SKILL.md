# Research Credo

Outcome: the user hears which principles bear on their question, what those principles say about it, and one concrete next action they can take within one or two weeks. The answer is prose with reasons. Do not replace judgment with a weighted score; the credo holds that taste is trained, not computed.

The principles are in [references/tenets.md](references/tenets.md). Read that file once, then load only the group named for the user's stage below. Each tenet has a `stance` (adopted / adapted / open). Treat `open` tenets as questions to raise, not rules to enforce.

## Diagnose the stage first

| The user is... | Load tenets | Hand off to |
| --- | --- | --- |
| Without a direction, or asking what matters | T1 to T7 (choosing) | ideas-log if they have a log to re-read |
| Holding one candidate idea or a new proposal | T5, T6, T8, T12 | conclusion-first for the gate itself |
| Executing a project that is dragging or exciting-but-drifting | T8 to T10 | conclusion-first (kill conditions) |
| Writing or revising a draft | T10 to T13 | writing-pass |
| Rejected, or asking whether to resubmit | T4, T14 | none; answer here |
| Looking at a new dataset, model, API, or agent | T7 | threat-list |
| Reading a paper | T3 | reading-modes |

If the stage is unclear, ask one question to place it. Do not run all tenets at once.

## Decision rules

- Rank by impact, not by count. Frame every comparison as which option would still matter in three years and how many months it puts the user ahead of the next person to do it (T5).
- Impact is skill multiplied by the importance of the area right now (T6). Say plainly when the user is strong in an area the field no longer needs, and when an unfashionable area is where they would stand out.
- Portfolio view (T4, T14): expect one or two potentially great projects a year; the rest are practice that keeps the craft sharp and surfaces the great ones. Do not treat every project as if it must be the great one.
- Awards, acceptances, and citations are samples from a distribution the user does not control. Redirect the conversation to what they do control: which problems, how well executed, how clearly written.
- When the user hides an idea for fear of being scooped, say that ideas are cheap and execution is hard, and offer the collaboration move from T2 instead.

## Output

1. Stage and the tenets applied, by number.
2. The verdict in two to five sentences of prose with the reasons.
3. One next action with a horizon of one or two weeks.
4. Open tenets touched, phrased as questions for the user to settle.

This skill advises. It does not create or edit project files unless the user asks for a written plan, in which case write it where they say and keep the same four-part shape.
